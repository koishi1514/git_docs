## 3. 架构对应（各层之间「怎么算」）

### 3.1 预序 → 亚历山大空间：怎么自动生成？

实现路径：

1. **输入**：一个符号集合 + 一个预序关系 `≤`（允许互含不等）。
2. **取上集判定**：实现一个谓词「子集 U 是不是上集」（含某元素则含其所有上方元素）。
3. **把谓词当开集定义**：直接把「是上集」接成拓扑的 `IsOpen` —— 即开集族 = 全体上集。这一步**不需要手写开集公理**。
4. **自动满足公理**：空集 / 全集是上集、上集对任意并与有限交封闭，这些性质由谓词本身给出，因此可直接注册成一个合法拓扑实例。
5. **附带标记**：该拓扑天然满足「任意多开集之交仍开」，可一并取得对应标记。

数据流：`预序` → `上集谓词` → `注册为拓扑（开集 = 上集）` → `Alexandrov 标记`

关键点：所谓「自动生成」，就是把上集谓词**直接当作 `IsOpen` 的定义**，拓扑公理无需单独证明。

### 3.2 亚历山大空间 → 海廷代数：开集格怎么算？

- 输入：空间 `X` 的开集族。
- 开集格 `Open(X)`：
  - 序 = 包含 `⊆`；
  - 交 `⊓` = `∩`，并 `⊔` = `∪`（可任意并 ⇒ 完全格）；
  - 顶 `⊤` = `X`，底 `⊥` = `∅`。
- **海廷蕴含**（关键，逐点计算）：
  - 一般拓扑：`U ⇨ V = interior(Uᶜ ∪ V)`；
  - 亚历山大空间（上集）：`U ⇨ V = {x | ∀ y ≥ x, y ∈ U → y ∈ V}`；
  - 否定：`¬U = U ⇨ ∅ = interior(Uᶜ)`；亚历山大情形 `= {x | ∀ y ≥ x, y ∉ U}`。
- 为什么是海廷代数：`Open(X)` 是 frame（无穷分配律）+ 相对伪补（由 `interior` 给出），满足伴随 `W ⊆ (U ⇨ V) ⟺ W ∩ U ⊆ V`。
- 计算要点：`interior` 是「最大的开子集」；在亚历山大空间即「最大的上集」。
- 对应实现：Lean `Opens X` 自动 `HeytingAlgebra`；已验证 `⇨` 即 `interior(Uᶜ ∪ V)`、伴随成立。

### 3.3 海廷代数 → 拓扑斯：子对象分类器怎么构造？

- 拓扑斯 = 范畴 + 有限极限 + **子对象分类器**（等价说法：幂对象）。
- 从空间 `X` 的海廷代数 `Open(X)` 出发：
  - 取 **层范畴** `Sh(X)`（`X` 上的层），它是一个拓扑斯。
  - **子对象分类器 Ω** 是一个层，`Ω(U) = {V | V 是 U 的开子集} ≅ Open(U)`（每个 `U` 处给一个海廷代数），限制映射 = 取交；`truth : 1 → Ω` 在每个 `U` 上选 `U` 本身。
  - 分类性质：`Sub(F) ≅ Hom(F, Ω)`（子层 ⟷ 特征映射 `F → Ω`）。
  - **关键**：`Ω(U)` 是海廷代数（即 `Open(U)`），所以拓扑斯的内蕴逻辑是**直觉主义 / 海廷的**——这就是 A4 与 A6 的接点。
- 一般（locale）情形：任何 frame（= 完全海廷代数）`H` 给出一个 locale，其拓扑斯 `Sh(H)` 的子对象分类器在 `top` 处的截面即 `H`。
- 对应实现：mathlib 无 `Topos` 类型类；用 `Sheaf.classifier J : Subobject.Classifier (Sheaf J Type)` 构造层拓扑斯的 `Ω`。

### 3.4 拓扑斯 → 层论：层怎么定义？粘合条件怎么算？

- 预层：`F : Cᵒᵖ → Set`（对开集 `U`，`F(U)` = `U` 上的局部数据，限制映射 `F(U) → F(V)` for `V ⊆ U`）。
- **层条件**（对覆盖 `{Uᵢ → U}`）：
  1. 局部：`sᵢ ∈ F(Uᵢ)`；
  2. 兼容：在重叠 `Uᵢ ∩ Uⱼ` 上 `sᵢ|_{iⱼ} = sⱼ|_{iⱼ}`；
  3. 粘合：存在**唯一** `s ∈ F(U)`，使 `s|_{Uᵢ} = sᵢ`。
- **粘合怎么算**：构造「兼容族」映射 `elementToCompatibleFamily : F(U) → CompatibleFamily`；**层条件 ⟺ 该映射是等价（双射）**——即「局部两两相容 ⟺ 存在且唯一的全局截面」。
- 上同调：`H⁰` = 全局截面；粘合失败（局部相容但无全局）的障碍在 `H¹`（更高阶障碍在 `H²`…）。
- 「和谐 / 违和」的对应：粘合成功、上同调为零 = 和谐；粘合失败、上同调非零 = 违和。
- 对应实现：cubical `Cubical.Categories.Site.Sheaf`（`CompatibleFamily`、`isSheaf`、`elementToCompatibleFamily`）；`Gluing.agda` 是它的有限具体版。

## 4. 任务实施方案（A1–A17）

### A1–A4 预序 → 亚历山大空间 → 开集格 → 海廷代数（已实现，Lean）

**对比**：

| 层 | 文档要求 | 实现 |
|---|---|---|
| **A1 预序** | 预序数据结构 | 由数据生成：JSON 原子关系 → 自反 + 传递闭包 → 全表；**点 = 原子属性（双层 `Pphy`/`Pmean`），SKU = 属性子对象** |
| **A2 亚历山大空间** | 自动拓扑化 | 通用构造：预序 → 上集拓扑（开集 = 上集），并认证为 Alexandrov 离散 |
| **A3 开集格** | 开集格生成 | 枚举全部上集作为开集，并与真实开集格对齐 |
| **A4 海廷代数** | 交/并/蕴含/否定 | 在开集上实现四运算，验证封闭性、蕴含伴随、非布尔，并与真实开集运算对齐 |

**A1 预序：数学定义**

数学：预序 `(X, ≼)` 满足自反（`x ≼ x`）与传递（`x ≼ y ∧ y ≼ z ⇒ x ≼ z`），并**允许互含不等**：`x ≼ y ∧ y ≼ x` 但 `x ≠ y`。

**（点 = 原子属性）**：预序的**点不是 SKU，而是原子属性**，分两层本体——`Pphy`（物理语义：面料 / 版型 / 尺寸 / 颜色 / 工艺…）与 `Pmean`（认知意义：场景 / 风格 / 身份…）；关系语义是 **`x ≼ y` ＝ 激活 `x` 可自发激发 `y`**（有向、非对称）。

SKU是属性的子对象，也就是它其实是物理属性和认知意义“点”的组合（`Pphy` 子集 + `Pmean` 子集绑定）。

开集就是认知开集,也就是认知邻域，一旦它包含某属性，就必须包含这个属性能激发（有预序关系的）出的所有属性。

注：允许互含不等对应的是一个**取商（偏序化）**操作——把互含的认知意义合并为同一个本体规格，即「认知意义 → 本体规格」的**离散化**；其范畴论表述（商映射 `q`、反向 `r`、伴随 `q ⊣ r`）在 A8–A10 接入。

**实现要点**：

- **A1 数据驱动**：
  - **真值源**：JSON 只存**元素表**与**原子关系**，不自存闭包。
  - **生成器**：校验数据 → 以**自反 + Floyd–Warshall 传递闭包**补出关系全表 → 以**暴力枚举子集**数出上集个数。
  - **Agda 侧产出**：生成元素类型与关系**全表**（`Unit` / `⊥` 类型版）；通用构造是**参数化模块**，在实例化文件里把元素类型与关系**代入**即可（无类型类、无需公理证明）。
  - **Lean 侧附加**：为生成的类型补齐**预序实例**与**可判定性**，并挂上通用构造的别名与上集个数。使得JSON数据适配成“能被 Lean 的数学结构辨认的形式”。通用构造对于被登记为预序的类型成立（把JSON数据变成Lean认可的预序）
  - **稳定别名**：当 JSON 标为「当前主预序」时，额外生成一个**别名文件**，把具体名（如 `Fashion`）统一映射到中性名（`Element` / `ElemSpace` / `ElemTopos`）。下游手写文件只写中性名，因此换JSON只需重跑生成器。
  - **通用构造**：`预序 → 空间 → 开集 → site → 拓扑斯 → Ω` 这条链与元素无关，只写成「给一个预序就能用」的通用定义；生成物负责把它**实例化**到具体元素（Lean 用类型类实例、Agda 用模块参数）。
- **A1 双层实现（当前）**：`data/ontology-retail.json`（`kind: ontology`、`main: true`）→ `Generated/Retail.lean` 已落地双层：
  - `Attr`（10 个原子属性）+ `Layer`（`phy` / `mean`）+ `layer : Attr → Layer`；
  - **激发预序** `Attr.relB` + `Preorder Attr`（`x ≤ y ⟺ 激活 x 可激发 y`）；
  - **~~Ω 场景池 `Scene`~~（已废弃）**：场景**不再是独立输入**，而是 `Ω` 的开集（认知邻域），应由属性算出；
  - **SKU 子对象** `Sku` + `skuAttrs`（物理 + 意义属性绑定）；**特征态射** `chi` 与**连带** `link`（海廷蕴含）——**目标口径**：`χ(SKU) = ↑(SKU 属性)`（一个认知开集），连带 = 在开集上做海廷蕴含；
  - 稳定别名 `Current.lean`：`Element := Attr`。
- **A2 预序 → 亚历山大空间**：把开集定义为**上集**——「含某元素，就必含它指向的所有元素」（`x ∈ U ∧ x ≤ y ⇒ y ∈ U`）。整套拓扑由这一条规则**唯一确定**，无需手写开集公理，并自动满足「任意多开集之交仍开」（Alexandrov 离散）。
- **A3 空间 → 开集（开集格）**：开集 = 上集。有限预序下把**全部上集枚举**出来，即得开集格；再证明「枚举出的上集就是真实开集」。
- **同一个开集在工程上有两种表示，Finset Element和Set Element（opens）**：
  - **Finset Element（可计算表示）**：元素的 `Finset` + 「是上集」（`allOpens`）；运算是我们按文档公式定义的 `meet / join / impl / neg`。能枚举、计数、判定。它列举出了开集包含的所有元素。
  - **Set Element（抽象表示）**：mathlib 的 `Opens ElemSpace`（真实开集）；运算是它自带的 `⊓ / ⊔ / ⇨ / ᶜ`。能推理、引用库引理，但不可判定。它通过“确定某一个元素是否在开集中”而定义开集。
  - **为什么会有两种**：`Finset`（元素列表）自带判等、枚举等算法，**能计算**；`Opens`（谓词式，`Set` 模外延相等）没有 `DecidableEq` / `Fintype` 实例，**不能计算**，无法回答「两个开集相等吗」「一共几个」。计算只能用前者、推理用后者。
- 由于A3层证明了枚举出的上集是真实开集。所以后续只需说明在**可计算表示**上的计算结果 = 真实开集上的结果，就可以说明我们定义的计算和真实开集上的运算是等价的。也就是证「我们四运算结果的**底层集合** = 真实开集对应运算 `⊓ / ⊔ / ⇨ / ᶜ`」（`meet_align`…`neg_align`）。（因 `Opens` 无 `DecidableEq`，对齐只能在底层集合层证。）
- **A4 领域断言**：开集数、四运算表、非布尔——在**可计算表示**上计算；由 A3（对象一致）+ 运算对齐（运算一致），结果对应真实开集格及其运算。
- **A4 的泛性质**：`impl` 还满足海廷蕴含的特征伴随（`impl_adj`）。

**A3/A4 枚举的区别（关键）**：

- **A4 的运算表是「闭包」命题**：「四运算作用在开集上，结果还是开集」。因 `X ∈ allOpens ⟺ IsUpper X`（A3 桥），这**等价于**一般定理 `isUpper_inter/union/impl`（对**任意**上集成立）。直接套一般定理即可（内容等价、瞬间）。原 `native_decide` 枚举 176×176 是**冗余**的。
- **A3 的开集数是「计数」命题**：「开集恰好有 176 个」。这是关于**这个具体预序**的数值事实， **必须枚举**（`native_decide` 枚举 2^10 个子集）。


**完整链路**：

**真实一侧（mathlib，抽象）**——`Opens` 由预序自动生成：
```
预序 Element
  │  WithUpperSet：把开集定义为上集
  ▼
亚历山大空间 ElemSpace
  │  Opens：取该空间的全部开集
  ▼
真实开集 Opens ElemSpace
```
（`Opens X` 是 mathlib 类型——「`X` 的开集」，即 `{ s : Set X // IsOpen s }`，**自动**带 `⊓ / ⊔ / ⇨ / ᶜ` 与 `HeytingAlgebra` 实例。）

**计算一侧（本项目，可判定）**——为能枚举 / 计数 / 判定，另建具体表示，并用两座桥钉回真实一侧：

```
计算                            桥 / 对齐                          真实开集
{Finset // IsUpper}  ──isOpen_finset_iff──►  Opens ElemSpace
   meet/join/impl/neg  ────*_align────►         ⊓ / ⊔ / ⇨ / ᶜ
```

**说明**：
- `derive_fintype%` 用于绕过 mathlib **#44243**（`deriving Fintype` 的 derive handler bug，v4.34.1/4.35 均复现，issue 仍 open）；关系用 `relB : Bool` + 显式 `DecidableRel`，使 `Decidable` 可用。
- 运算对齐在**底层集合层**（`(↑… : Set) = …`），因 `Opens` 无 `Fintype`/`DecidableEq`；但"底层集合一致 + 都满足 `IsOpen`"已足以说"运算相同"。


### A5 直觉主义逻辑引擎（已实现，Lean；求值 + 演绎）

A4提供了一套自定义的，符合海廷代数逻辑的运算（`⊓/⊔/⇨/ᶜ`，作用在真值 / 开集上）(语法)。计算一个**复合命题**（如「P 且 Q」「P 蕴含 Q」）的真值，需要先将复合命题表示出来，再将表示的命题翻译成A4的运算以求值。

A5 提供了`Formula`（代码语言，负责求值过程的表示）和 `eval`（求值，实现计算）：

- `Formula`由 `atom` / `⊥` / `∧` / `∨` / `→` 搭成的**表达式（数据）**。例：命题「`P ∧ Q`」写成 `and (atom P) (atom Q)`——它本身只是一个**还没被解释的式子**。
- `eval` 才把 `Formula` 接到 A4：把每个连接词**换成对应运算**（`∧↦⊓`、`∨↦⊔`、`→↦⇨`、`⊥↦⊥`），于是式子变成一个**真值**。
**实现逻辑**

- **三个部件（关键）**：
  - **语法 / 对象语言**：`Formula`（原子 + `⊥`/`∧`/`∨`/`→`）。**不用 Lean 的 `Prop`**：`Prop` 是 Lean 的**元语言**（用于证明），由于它可取排中律，且不可计算。
  - **真值域**是一个命题的取值能取到的所有值组成的集合。经典逻辑的真值域是 `{真, 假}`。这里允许更一般的真值域，用一个 **Heyting 代数 `H`** 表示——即「真值的取值范围」，并且它自带运算（怎么「且 / 或 / 蕴含」）。A3/A4 造的开集格 `Opens ElemSpace` 就是一个真值域（真值 = 开集）。
  - **赋值**：`v : Atom → H`——给每个**原子**（原始意义 / 判断）指定一个真值。
- **求值（eval）**：把赋值从原子**递归**扩到整个公式——把每个连接词换成 `H` 的对应运算。下面 `↦` 读作「**求值为**」：
  - `atom a ↦ v a`：原子 `a` 的真值 = 赋值给它的 `v a`；
  - `⊥ ↦ ⊥`：「假」求值为代数底元 `⊥`；
  - `φ∧ψ ↦ eval φ ⊓ eval ψ`：先分别求 `φ`、`ψ` 的真值，再取 `⊓`（代数里的「且」）；
  - `φ∨ψ ↦ eval φ ⊔ eval ψ`：同理取 `⊔`（「或」）；
  - `φ→ψ ↦ eval φ ⇨ eval ψ`：同理取 `⇨`（蕴含）。
- **与 A4 的关系**：A3/A4 定义了**真值域**（开集格 + `⊓/⊔/⇨/⊥`），A5 完成了**语言 + 求值**——把复合意义计算成真值域里的元素。本质上，A5 对任意 `H` 通用：把 `H` 取成 A4 的开集格即接上 A4，连接词用的正是 A4 的四运算。

**演绎（推理引擎）**：从「已有事实 + 规则」**正向链式**推出「新事实」（即文档的「演绎数据库：规则推理、新事实生成」）。

- 事实就是复合命题中的原子+它的真值，
- **Horn 规则** `前提₁ ∧ … ∧ 前提ₙ -> 结论`：如果这些前提都成立(合取)，那么可以推出这个结论。前提都成立->结论成立，基本推理规则。
- **环境**：`原子 → 真值`，即当前事实。
- **单步演绎**：每个原子的新真值 = `旧真值 ⊔ 以它为结论的规则体真值的并`；规则体真值 = 前提真值的合取 `⊓`；多个规则指向同一结论时取 `⊔`。反复 `step` **迭代至闭包**（不动点）。
- **可靠性**：若环境**已满足全部规则**（规则体 ≤ 结论），则一步演绎不变——它已是模型 / 不动点。


**为什么采用「求值 + 演绎」**
- 对应文档 A5 的两个功能：**复合逻辑**（把复合意义算成真值）= 求值；**演绎数据库**（事实 + 规则 → 新事实）= 演绎。
- 求值是「非二值真值」的落地：把公式求值到海廷代数，即得「既非真也非假」的中间真值（对应「三种信念状态不是非真即假」「结构偏离度是直觉主义真值」）。
- 演绎是「推理」的落地：正向链式传播 + 闭包，对应「演绎数据库」与「因果信念滤波」。
- **未覆盖**：判定任意直觉主义公式是否有效（证明搜索 / 判定）——这需要先建**证明系统**并证明其**可靠性与完备性**，本工程未做。

### A6–A7 拓扑斯构造与子对象分类器（已实现，Lean）

**链路**（全在通用文件 `ConsGen/Core.lean`，对**任意 `[Preorder α]`**(预序)通用；预序输入后, 后续的构造由 mathlib 自动完成）：

```lean
abbrev Space   (α) [Preorder α] := Topology.WithUpperSet α                 -- 1
abbrev OpensOf (α) [Preorder α] := Opens (Space α)                        -- 2
abbrev SiteOf  (α) [Preorder α] := Opens.grothendieckTopology (Space α)   -- 3
abbrev ToposOf (α) [Preorder α] := Sheaf (SiteOf α) (Type _)              -- 4
def    OmegaOf (α) [Preorder α] : Subobject.Classifier (ToposOf α) :=
                     Sheaf.classifier (SiteOf α)                         -- 5
```

每一步从预序获取什么信息?

| 步 | 得到 | 机制 |
|---|---|---|
| **1 预序 → 空间** | **开集 = 上集**（`x∈U ∧ x≤y ⇒ y∈U`）= 认知邻域 | 把「上集」直接当作开集（拓扑公理由此自动满足）|
| **2 空间 → 开集格** | 开集全体，**自动是海廷代数** | 取该空间的开集族 |
| **3 开集格 → site** | **开集范畴**（对象 = 开集，态射 = 包含）+ **覆盖拓扑** | 在开集范畴上规定「哪些小块覆盖大块」|
| **4 site → 拓扑斯** | site 上的**层范畴**（Grothendieck 拓扑斯） | 取「满足粘合条件」的层全体 |
| **5 拓扑斯 → Ω** | **子对象分类器** | 取该层范畴的子对象分类器 |

**关键概念（用 Retail 预序具体化）**：

- **开集 = 上集**：如 `↑丝绸 = {丝绸, 优雅, 约会}`、`↑修身版型 = {修身版型, 优雅, 约会}`。
- **覆盖 = 用一族更小的开集把大开集「拼满」**：
  `U = {丝绸, 修身版型, 优雅, 约会}` 被 `V₁ = ↑丝绸` 与 `V₂ = ↑修身版型` **覆盖**（`V₁ ∪ V₂ = U`），二者**重叠** `V₁ ∩ V₂ = {优雅, 约会}`。
  - **为什么需要它**：没有覆盖，你只知道「**有哪些区域**」，不知道「**谁拼得成谁**」，只能孤立地讨论单个区域。
  - 有了覆盖 / 重叠，才能做**局部 → 整体**：① 只在**小块**上给数据（局部、容易）；② 检查小块在**重叠**处是否**矛盾**；③ 若不矛盾 ⟹ **唯一**地得到大块的数据；
  - **这正是「局部判断粘合为整体判断」的机制**（文档第 5 层的核心）。
- **site = 开集 + 覆盖概念**（`Opens.grothendieckTopology`）：规定「**哪些小块能覆盖大块**」。
- **预层 `F` = 「按区域配数据」**：给每个开集 `U` 指定一个**集合** `F(U)`，其元素是「**在 `U` 上能看到 / 挂载的数据**」。
  - 例：`F(U)` = 在 `U` 上成立的**局部判断**集合；或 `F(U)` = 在 `U` 上挂载的**局部统计数据**（连带率 / 毛利 / 成交频次）。
  - dummy 统计数据已就位（`data/transactions/retail.json`，购物篮形式、只引用 SKU）；它可按 记录 → SKU → 属性 → 开集 → `F(U)` 挂载，用来演示连带率 / 毛利。但当前代码还没有读取 / 挂载它的逻辑（仍是设计），且为安全放在了子目录。
  - **限制**：若 `V ⊆ U`（小区域含于大区域），则有 `F(U) → F(V)`（把大区域的数据**缩小**到小区域）。
- **层 = 满足「粘合条件」的预层**：对覆盖 `U = ∪Vᵢ`，局部数据在**重叠处相容** ⟹ 存在**唯一**整体数据 `∈ F(U)`，限制到每个 `Vᵢ`。
- **三部件与层范畴**：层范畴 `Sheaf J Type` 是一个**范畴**；**有限极限 / 笛卡尔闭 / 子对象分类器**是它的**三个性质**；`IsTopos` 把这三条**打包**成一句「它是拓扑斯」。（mathlib 这三个类各自独立、**无统一的 `Topos` 类**，故自研组装。）

**认证**（`Topos.lean`）：用自研类 `ConsGen.IsTopos`（`ConsGen/ToposAxioms.lean`：有限极限 + 笛卡尔闭 + 子对象分类器）认证 `ElemTopos` 是**初等拓扑斯**。

**内蕴逻辑**：`Ω` 的取值（开集）构成海廷代数，故内蕴逻辑是直觉主义的（与 A4 的接点）。

### A8 范畴论库集成（已实现，Lean）

- 落地：`CategoryTheoryDemo.lean` 在**开集范畴** `C := Opens ElemSpace` 上演示对象 / 态射 / 复合 / 恒等（`𝟙`、`≫`）。

### A9 函子、自然变换、单子（已实现，Lean）

**目标**（文档第 3 层）：用「对象 / 态射 / 函子 / 自然变换 / 单子」组织各层接口——对象 = 状态 / 情境，态射 = 意义转换，复合 = 路径连接，恒等 = 同一性。

**实现逻辑**（`CategoryTheoryDemo.lean`，载体 = 开集范畴 `C := Opens ElemSpace`）
- **范畴的载体**：预序即范畴（mathlib `Preorder → Category`）——对象 = 开集，态射 = 包含，复合 / 恒等由传递性 / 自反性给出（**thin category**）。
- **函子**：thin category 间函子 = 保序映射；`Functor` 自动满足 `F(id)=id`、`F(g∘f)=F(g)∘F(f)`。
  - `𝟭 C`（恒等）；`meetF U : X ↦ X ⊓ U`、`homF U : Y ↦ U ⇨ Y`（由 `functorOfMonotone` 从单调映射构造）。
- **自然变换**：`NatTrans`；thin category 上 = 逐点 ≤（自然性自动，`Subsingleton`）。例：`meetToId U : meetF U ⟶ 𝟭`（分量 `X ⊓ U ≤ X`）。
- **单子**：经**海廷伴随** `meetF U ⊣ homF U`，由 `Adjunction.toMonad` 得到（`heytingMonad U`）。

**说明**：预序当作范畴时，两对象之间的态射**至多一个**（「能到」或「不能到」）。于是范畴概念具体化为：**函子** = 单调映射；**自然变换** = 逐点比较；**伴随** = Galois 连接。这正是选预序作为「认知意义骨架」的原因——范畴结构简单、可判定。

### A11–A13 同伦类型论基础（已实现，cubical）

**目标**（文档第 1 层）：给整个架构一个「类型 = 空间」的基础语言——把「认知意义」当作类型、「意义转换」当作路径，并支持**三层同伦**（路径 / 同伦 / 高阶同伦）。

**一、「类型 = 空间，项 = 点，路径 = 相等，等价 = 同构 = 同胚」怎么构造（A11–A12）**

1. **类型 = 空间**：把类型当空间，用 `Unit` / `Bool` / `S¹` 当三种空间。
2. **项 = 点**：空间的元素即点（`tt` / `true` / `base`）。
3. **路径 = 相等**：用 cubical 的**路径类型** `x ≡ y`；恒等 `refl`、复合 `_∙_`、逆 `sym`（群胚结构）。
4. **等价 = 同构 = 同胚**：先给**同构** `Iso`（一对互逆映射），再用 `isoToEquiv` 得到**等价** `Equiv`——故等价 = 同构。
5. **univalence（A12）**：用 `ua` 把「等价」提升为「路径」（如 `Bool ≡ Bool`）；`uaβ` 保证「沿路径 transport 就是执行那个等价」。

实现文件：`ConsGen\HoTT\Basic.agda`（A11）、`ConsGen\HoTT\Univalence.agda`（A12）。

**二、三层同伦的实现（A13）**

| 层 | 构造 | 类型 | 载体 |
|---|---|---|---|
| **1 路径** | `loop : base ≡ base` | 点之间的路径 | S¹ |
| **2 同伦** | `surf : refl ≡ refl` | 路径之间的路径 | S² |
| **3 高阶同伦** | `surf`（三维胞腔） | 同伦之间的路径 | S³ |

- **机制**：路径 = cubical 的路径类型；**高阶路径 = 路径类型的嵌套**（2-路径 = 路径之间的路径，3-路径 = 2-路径之间的路径，可无限往上 = ∞-群胚）；**非平凡高阶路径由 HIT 的高维构造子给出**（`loop` / `surf`），否则普通类型里的高阶路径都是平凡的。
实现文件：`ConsGen\HoTT\HigherHomotopy.agda`。

## 5. 关键限制与栈间差异

- **Lean 不支持 HoTT**（UIP + strict Prop），故 A11–A17 必须用 cubical，两者靠数据桥对接，非内核统一。
- **mathlib 无 `Topos` 类型类**：A6 以层范畴 + 子对象分类器实现；内蕴逻辑（Ω 上的 Heyting / HOL）无高层 API。
- **预序 → 拓扑斯：cubical 也能做，Lean 更省力**。cubical 侧同样可以构造——用「预序 + 上集格」定义亚历山大空间，再搭出开集格与层范畴（cubical 有范畴 / site / 层设施）。差异在于：Lean 有现成的 `TopologicalSpace` / `Opens` / `HeytingAlgebra` / `Sheaf` 实例，**几乎零代码自动接上**；cubical 侧这些要**自搭**（没有现成的拓扑空间 / 海廷 / 拓扑斯类），需手写结构与证明。这正是把 A1–A10 放在 Lean 的原因。

## 6. 现实场景 × 预序：SKU 与连带的语义模型

### 6.1 输入 = 原子概念 + 预序（点不是 SKU）

系统输入：**一组原子概念** + 它们之间的**预序 `≼`**。概念分两层本体：

- **`Pphy` 物理语义本体**（客观、稳定、刚性）：面料、版型、尺寸、颜色、工艺、成本、供货周期……
- **`Pmean` 认知意义本体**（主观、柔性、场依存、可被供给重塑）：穿搭场景、风格叙事、功能认知、身份感知、搭配预期、仪式感……

预序：**`x ≼ y` ＝ 激活 `x` 可自发激发 `y`**（自反、传递、**非对称**）→ 有向（`A 带 B ≠ B 带 A`）。

### 6.2 SKU = 子对象（属性子集绑定）

**SKU 不是预序的点**，而是 `P` 的**子对象**：

> **SKU = 一个 `Pphy` 子集 + 一个 `Pmean` 子集的绑定聚合。**

即：SKU 是「属性集合的子切片」，由「从两个本体各取一个子集、再绑定」得到。

### 6.3 连带 = 有向命题 `A ⇒ B` 的可构造性

- 连带不是 SKU 间的**统计相关**，而是属性激发链传播后的**高阶涌现**；
- **连带成立 ⟺ 命题 `A ⇒ B` 可构造**（直觉主义：真 = 可构造）；
- **有向**：问的是 `A ⇒ B`，不是 `B ⇒ A`。

### 6.4 链路（拓扑斯工程）

```
预序 (Pphy ∪ Pmean, ≼)                     输入：原子属性 + 激发关系
   │ 亚历山大语义拓扑：开集 = 认知邻域（上集）
   ▼
Ω = 有限离散场景池（子对象分类器 = 海廷代数）
   │ 特征态射 χ : SKU → Ω 子集
   ▼
⟦A ⇒ B⟧ = { ω | ω ∩ χ(A) ⊆ χ(B) }          （海廷蕴含）
   ├ ≠ ∅ → 可构造 → 进入概率/毛利计算
   ├ = ∅ → 不可构造 → 直接剔除
   └ = ⊤ → 全局成立
   │ 层：每个场景 ω 挂载 连带率 / 毛利 / 成交频次 / 约束
   ▼
采购决策：稳态优化（弱干预） / 相变风控（强干预）
```

### 6.5 成交 = 构造的见证（非判据）

- 成交记录 = 一次「构造发生过」的**痕迹**（认知耦合收敛后留下的结构）；
- 它并非不是**判据**：可构造**未必**有成交（稀疏）；成交**未必**是真构造（噪声）；**相变后历史成交失效**；
- 先由逻辑（预序 + Ω）判定可构造，再用层数据量化（可构造优先于概率）。

### 6.6 三层高阶（一阶在预序、二阶在 Ω、高阶在函子）

**判据：「阶」= 你在讨论哪一层的东西**——两端是**点** → 1 阶（关系）；两端是**关系** → 2 阶；两端是**整个结构** → 高阶。

| 你讨论的两端 | 阶 |
|---|---|
| 点（属性） | 1 阶（关系）|
| 关系（命题 / 真值） | 2 阶 |
| 整个结构（预序 + Ω） | 高阶 |

**一阶：预序内部（对象语言）**
- 论域：属性（`Pphy` / `Pmean` 的点）；
- 含义：属性之间的**激发** `x ≼ y`，从 A 能不能走到 B（属性层面）；
- 运算：**传递闭包**（把激发链接起来）；
- 产物：SKU 连带网络（谁可达谁，如 `蛋糕 ≼ 生日场景 ≼ 蜡烛`）；

**二阶：`Ω` 层（元语言）**
- 论域：关系 / 命题；
- 含义：一条关系**是否有效**（这条 `A⇒B` 在哪些场景成立）「干预是否销毁其有效域」「预序是否偏移」；
- 载体：`Ω`（子对象分类器 = 场景池 = 海廷代数），给命题赋真值（开集）；
- 产物：每条连带的**有效域** `⟦A⇒B⟧ = {ω | ω∩χ(A) ⊆ χ(B)}`；
- 问：**这条关系在哪些场景成立、有效**（对关系下判断）；

**高阶：函子层**
- 论域：**整个结构**（预序 + `Ω` + 真值体系）；
- 含义：**改写**预序、**重构** `Ω`、**替换**真值体系；
- 载体：**函子**（把「一个 (预序, Ω) 体系」整体映射成另一个）；
- 产物：**拓扑相变**（结构本身变了，不是量变）；
- 问：**整个体系怎么变**（变换结构）；

**统一例子（蛋糕 / 蜡烛 / 生日）**

| 层 | 说法 | 结果 |
|---|---|---|
| 一阶 | 属性激发链 `蛋糕 ≼ 生日场景 ≼ 蜡烛` | 从蛋糕**可达**蜡烛 |
| 二阶 | 命题「`蛋糕⇒蜡烛` 在哪些场景成立」在 `Ω` 上求真值 | 有效域 `⟦蛋糕⇒蜡烛⟧` = {生日场景, …} |
| 高阶 | 强干预：**删掉"生日场景"**（改写预序 + 重构 Ω） | 有效域**整体失效** → 拓扑相变，旧统计作废 |

**二阶 vs 高阶 的关键对比**：
- **二阶**：场景**没变**，只是问"关系在这些场景里成立吗"——**量的变化**（有效域变大变小）；
- **高阶**：场景 / 预序**本身被改写**（`Ω` 重构、可达路径增减）——**质变**（真值体系换了，旧的一切失效）。

相变判定的两条（文档）：任意两条 `A⇒B` 的 `Ω` 有效域**性质**变了，或**预序可达路径**增减 → 结构破缺（相变）。

**为什么会这样分层**：这是**反思层级**的递进——一阶谈"属性"（对象层）、二阶谈"关系是否有效"（元一层）、高阶谈"结构怎么变"（元二层）。每上一阶，被讨论的东西就"整体"上一层：点 → 关系 → 结构。

一阶关系：讨论的是点（属性，物理/认知意义）
二阶关系：讨论的是关系（命题/真值）
高阶关系：讨论的是结构（预序 + Ω 本身）

### 6.7 与现有实现的差距

| 文档要求 | 现状 |

## 7. 四层结构：数学基础 / 本体 / 业务 / 任务

代码按「内容性质 + 变化来源」分四层（越往下越接近数学、越往上越接近业务）。

### 7.1 每层（内容 / 变化 / 来源 / A-task）

- 数学基础层：`预序→空间→开集→site→拓扑斯→Ω`（`ConsGen/Core.lean`）、海廷四运算（`Heyting.lean`）、直觉主义逻辑引擎（`Logic.lean` / `Deduce.lean`）、`IsTopos`（`ConsGen/ToposAxioms.lean`）、范畴论工具（`CategoryTheoryDemo.lean`）。对应 A2–A9。
- 本体层：属性的概念空间——`Attr`（物理 / 意义双层）+ 激发预序 `≼`，喂给数学基础层即得空间 / 开集 / 拓扑斯 / Ω。「本体」= 属性，不含 SKU（SKU与业务相关，这一层只有最基础的本体/属性）。
- 业务层：业务场景的构造——`Sku`（属性绑定 = 子对象）、`χ`（SKU → 认知开集）、`link`（连带 = 海廷蕴含），以及统计数据（篮子 → `margin` / `support` / `crossRate`）。从 `sku-*.json` + `transactions/*.json`这两个外部输入产生；复用 A3/A4。
- 任务层：决策目标——`Task`（采购 / 销售）、选择子（`taskConcepts` / `taskSkus`）、业务函子 `L`（结构 → 预算）。来源 `tasks/*.json`；对应 A8/A9（函子）。

数学基础层是系统的基础，它不随着业务场景或者决策目标的改变而改变。

### 7.2 三处关键区分

- 本体 ≠ 业务：本体 = 属性（概念空间）；SKU 不是本体，是业务层从属性绑定出的实体（换业务场景可能没有「SKU」）。
- 任务 ≠ 场景：任务是决策目标（采购 / 销售）；「认知场景」= `Ω` 的开集（认知邻域），二者不同。
- 任务只选取概念（选择子）并定业务函子，不改写激发关系。

### 7.3 选择子（任务如何选取相关）

- 任务给定 `taskConcepts`（它关心的概念）；
- 相关 SKU = `{ s | skuAttrs s ⊆ taskConcepts }`（概念包含：产品完全由选中的概念构成）；
- 例（采购）：`红色连衣裙 = {red, dress, date}` 含 `date ∉ 选中集` → 被剔除；`丝绸连衣裙` / `羊毛外套` 留下 → 选择子真的生效；
- （备选口径 `χ s ⊆ ↑taskConcepts` 保认知开集，但本数据下 = 全域；本工程取概念包含。）
